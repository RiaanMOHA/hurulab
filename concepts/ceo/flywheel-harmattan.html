The two engines of high margin: owned GPUs and token efficiency

COGS gets flattened by two moves: compute goes from rented to owned, and tokens go from “blast everything at the flagship” to “cache first, then route.”

1. Local GPUs, variable becomes fixed

The traditional approach rents compute from cloud providers by the hour and by the token, so costs climb in lockstep with users. Buying GPUs turns compute into a one-time capital asset, and as traffic explodes, the cost spread across each user shrinks toward zero.

2. Token efficiency, algorithmic savings

The traditional approach blasts every query at expensive frontier models, eating 30 to 50% of revenue. Prompt caching, model routing, easy tasks to small local open-source models, and semantic search slash the remaining external API dependency by 80% or more.

MetricTraditional AI businessAI network modelFinancial impact
API and token expense30 to 50% of revenue 2 to 5% Caching plus small local models keep external calls minimal.
Hosting and compute15%, cloud markup 2%, electricity and colo Owning the hardware keeps the cloud provider’s margin in your pocket.
Total cost of goods sold45 to 65% under 10% The bigger the scale, the closer expenses get to zero.
Gross margin35 to 55% 90%+ Software-like scaling with a deep-tech moat.

Variable cost becomes a fixed asset. Cloud bills grow with traffic; owned GPUs are bought once, so the more traffic, the closer each user’s share of cost gets to zero, and the remaining external API dependency gets cut another 80 percent by caching and routing.

The scale inflection: a cost-per-query waterfall

X is monthly query volume on a log scale. The cloud API costs the same every single time; owned GPUs, once saturated, send the per-query cost crashing down like a waterfall.

Volume is your friend. The cloud line lies at 1 cent forever; owned compute plunges past the inflection point and keeps falling, so scale stops bringing bills and starts bringing advantage. This is the visual proof that network capabilities scale painlessly.

A flywheel is not a flowchart. It has no finish line: output improves, both cities rely on it more, usage grows, the engines upgrade again. The more a network is used, the more it is worth to every member.

The data flywheel’s reinforcing loop

The general principle behind the wheel above. The R at the center is the systems dynamics mark for a reinforcing loop: this is no ordinary cycle, because every completed turn makes the next one faster and bigger.

Cause runs in one direction only. More users, a bigger data pool, sharper patterns, a better product, which attracts more users again. The R mark is the reminder: this system self-accelerates with scale, and it does not stop on its own.

One stream of data in, four streams of patterns out. This is how people with similar usage share a network effect, and a new member, drawn dashed, inherits everything the network has already learned on day one.

How many turns until it kicks in: the inflection

X counts flywheel turns on a log scale. The left axis is effort per member, falling from a high start; the right axis is whole-network efficiency, flat and then exploding. The moment the two lines cross, network effects officially take over.

Effort per member, left axis, index Network efficiency, right axis, index

Before critical mass, people push; after it, the network pushes itself. The early turns are expensive, every rule written by hand, every error fixed by hand. Past the inflection point, the accumulated data starts working on everyone’s behalf: effort collapses and efficiency takes off.

How fast a new member gets value: the ski slope

Every extra turn of the flywheel shortens the next member’s time from joining to seeing value. On turn 1 it takes 30 days; by turn 50, just 30 seconds.

This is the network’s compound interest. The data and rules Kumamoto and Tokyo spun up all live in the network; a new city plugs in and starts on turn 50 from day one, with no climbing the slope again.

04 · The big loop

The whole page, folded into one loop

Each of the first three sections is a node; chained together, they are Hurulab’s big flywheel. Every plus marks reinforcement: AI saves time, software turns time into margin, margin feeds the network, and the network makes AI stronger in return.

The big flywheel, every turn faster

Step through the four links and watch each one reinforce the next.

THE ENGINE AI, LLM automationtime and token savings

THE AMPLIFIER Network effectsmore users → more data
THE OUTPUT Capabilitiesadvanced features · scale
1. Engine → Fuel, reinforced

Near-instant generation and automation cut research and operating time to the bone, while routing sends every token to the cheapest capable model. Time and token cost together trigger software economics.

2. Fuel → Amplifier, reinforced

Serving the next user costs almost nothing. The freed capital plus friction-free distribution goes into aggressive user acquisition and infrastructure reinvestment, feeding the flywheel.

3. Amplifier → Output, reinforced

More users mean more data, sharper-tuned models, and denser node connections. What the network can physically do grows outward on its own.

4. Output → Engine, reinforced

Higher capabilities hand AI better context and tools, and proven methods feed back to sharpen the router: it learns which model is enough for which task and hits it on the first try. Time and tokens both save harder, and the loop returns to the start, spinning faster.

Where this loop ends is a moat. The system gets smarter and faster, and every turn makes it harder to copy, because what competitors would have to chase is not a feature but the entire loop.

05 · Design notes

Why the page is drawn this way

This page is itself a design exploration. Four principles, drawn from research on flywheel diagrams and the visualization of software economics.

ONE IDEA PER VIEW One idea per screen

Shared engines and margin tell the same story, so they share a section, but every board still gets exactly one interaction. Cramming everything into one figure is where spaghetti diagrams begin.

FIVE NODES AT MOST Five nodes at most

The research consensus: past five nodes, readers lose the self-reinforcement thread. This page uses four, with the hub reserved for the shared engines.

INTERACTION OVER ANNOTATION Let people press, not read

The second tenant is almost free is a claim when written; pressing the plus and watching the margin jump is a feeling. Causality is proven by interaction.

MOTION IS MOMENTUM A flywheel has to move

The point of a flywheel is momentum: one more use, a little more speed. A static circle is just a cycle diagram; a circle that accelerates is a network effect.

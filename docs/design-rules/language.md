# The design language

**Big, bold, bento, and very Apple.**

The owner's words, 30 July 2026. This is the governing idea of the whole system. Every other
file in this folder is a consequence of it, and every value in them should be traceable back to
one of these four words. If a rule cannot be, it is decoration and it should be deleted.

Read this before any other file here.

## The three references, in priority order

Owner decision, 31 July 2026. When they disagree, the earlier one wins.

1. **Apple.** Restraint, enormous space, huge type, near monochrome, one color used once.
2. **The Lovable build**, `hurulab-codebase`. Where the bento, the radii, the button shape, the
   motion and the copy rules come from. It is the working reference for structure.
3. **ajsmart**, for simplicity and clarity only. Short declarative lines, one statement per
   section, nothing crowded. Not its palette and not its typefaces.

This order is why the accent is used once per view rather than spread around, and why the page
is near monochrome with a single color doing the marking.

---

## Big

**Type is the primary visual element. There is no hero image, and there is no illustration.**

- Statement type runs to the top of the scale, near 126px at desktop with h1 at Apple's own
  hero size, and sits alone at the top of every section.
- Vertical space is generous to the point of feeling expensive: `6rem` of section padding rising
  to `8rem`.
- Text runs full width to the section padding. No narrow reading column.

The test: **if you removed every color and every border, would the page still have a structure?**
If the answer is no, the type is not doing enough.

## Bold

**High contrast, and no hedging.**

- Weight 700 at `-0.04em`, near-black on white.
- Two colors and one accent. No mid-tone palette, no timid secondary hues.
- Important words are never set in grey. The grey half of a two-tone heading is always the setup,
  never the claim.
- One primary action per view, and it names what it does.

The test: **can you tell what the section is about from across the room?**

## Bento

**Unequal tiles composed into a grid, not equal tiles filling one.**

This is the word most likely to be lost in implementation, because the lazy version of it is a
card grid, and a card grid looks reasonable.

- Tiles **span**: the lead tile takes both columns.
- Tiles **differ in height** on purpose, so the composition has a silhouette.
- Tiles **differ in fill**: dark, light, outlined, alternating on a rhythm.
- Tile internals stay identical, which is what allows the outer sizes to vary without chaos.

The test: **could this section have been generated by mapping over an array?** If yes, it is a
card grid and the language is gone.

Full mechanics in [layout.md](layout.md) section 4.

## Very Apple

**Restraint doing the work, and precision as the finish.**

This word is the most misread. It does not mean Apple's materials. It means Apple's confidence.

What it does mean:

- Every element earns its place, or it is removed.
- Motion is precise, brief and unshowy. One easing curve, durations matched to the size of the
  thing moving.
- Nothing decorative. No element exists to fill a space.
- Detail is exact. Values are chosen, not defaulted, and a `4px` corner in a `1.75rem` system
  reads as a mistake.

What it does **not** mean, and this is the failure mode:

- **No glassmorphism, blur, glow, or frosted panels.** The value-add prototype killed frosted
  glass across all 20 steps and rebuilt the depth from a 1px border and a shadow. That is the
  precedent.
- **No gradients**, in fills or in text.
- **Nothing floats at rest.** Shadow appears on hover as lift, and at no other time.

The test: **would removing this element make the page worse?** If not, remove it.

## How the four resolve conflicts

They are listed in priority order. When two pull against each other, the earlier word wins.

- **Big beats bento.** If a tile arrangement forces the statement type smaller, the arrangement
  is wrong.
- **Bold beats very Apple.** Restraint is not the same as quiet. When a claim matters, it is
  large and near-black, not softened.
- **Very Apple beats everything on detail.** A composition that is right in structure and sloppy
  in execution has failed, and nothing earlier on this list rescues it.

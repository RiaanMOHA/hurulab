## Problems encountered and how they were solved

- **`layout_update` "old_string not found" at board scope for frame children.** The first shift attempt on step 11 used the plain board URL (`.../uXjVH-umqy4=/`) and failed, because a board-scope read/update does NOT include frame children in the DSL. **Fix:** target the frame by appending `?moveToWidget=<frameId>` to the `miro_url` for both the read and the update. Once scoped to the frame, the child SHAPE lines matched and updates succeeded. This was the same class of failure the prior session hit repeatedly on step 11 — the real cause was scope, not the apostrophe or drift as earlier suspected.
- **A wasted `layout_update` call** where I put the new value into the `old_string` field (matching new==old). It failed harmlessly ("not found"). Lesson: double-check old vs new before firing.
- **Apostrophe rendering.** Prior session found apostrophes stored literally but shown as `&#39;` in some reads. In this segment, once frame-scoped, the DSL showed `Henry's` literally and matches on the coordinate substrings (`x=650 y=290 w=920`) avoided the apostrophe entirely, so no issue. Matching on coordinate/geometry substrings rather than on text content is the robust approach for repositioning.

## Learnings and discoveries

- **Frame-scope every child edit.** To read or find/replace a frame's children with `layout_read` / `layout_update`, the `miro_url` MUST include `?moveToWidget=<frameId>`. Board-scope only returns top-level frames, docs, tables, and cross-frame connectors.
- **Match on geometry, not prose, when repositioning.** Using `x=650 y=290 w=920` as the find target is unique-enough per box and sidesteps apostrophe/entity-encoding mismatches in text content.
- **Connectors are id-anchored.** Moving/resizing a shape does not break connectors that reference it; they re-anchor automatically. No need to touch connector DSL when shifting boxes.
- **The frame grid is actually coherent** (contrary to the prior session's "scattered" worry). All 12 step frames sit on one row at y=-2424.19, spaced ~1500 apart left to right in step order. Reference DOCs/TABLEs sit above at y≈-5320. The timeline frame sits below at y=-71. Minor inconsistency: step 9's frame is w=1200 while the rest are w=1300 (its children fit; left alone to avoid re-centering risk).
- **User preferences reconfirmed:** cold neutrals only; every frame must be visual and carry real explanation, not one-word labels ("just words" / "are you fucked in the head" were the reactions to shallow frames); never invent content, only use the interviews; Hurulab is always one word; "lead designer" never "senior"; sentence case, no title case, no uppercase, no emojis, no em/en dashes; be concise; the board stays ON Miro (rejected slide-deck/HTML alternatives).
- **Coming-soon page mechanics:** it uses a fixed-center crossfade — a `.stage {position:fixed;inset:0}` holds 7 `.beat` divs (6 text + 1 final email beat), each absolutely centered; opacity is driven by scroll via `render()` computing `p = scrollY/vh` and `opacity = max(0, 1 - abs(p-i)/0.7)`. A `.track` of one 100svh snap `<section>` per beat provides scroll length. Text must stay dead center and only fade (user explicitly rejected any scroll-up-and-off motion and rejected scroll-snap that moved text).

## Architecture and design notes

- **Board layout shape:** three horizontal bands. Top band (y≈-5320): reference DOCs and TABLEs (Read me first, Taiwan competitive landscape table, master SWOT, positioning doc, international benchmarks table, roadmap/brand/voice/case-story docs) — the evidence layer. Middle band (y=-2424): the 12 step frames left to right in order — the stakeholder-facing strategy. Bottom band (y=-71): the 12-step progress timeline with "we are here" on step 2. This ordering was a deliberate fix from the prior session ("move it up" — reference above the strategy, not on top of it).
- **Frame visual pattern for a "deep" step:** a header/subtitle TEXT at top, primary visual shapes (funnel boxes, attribute cards, columns, named-voice panels) with a bold black emphasis element for the payoff line, plus small grey (#555555) caption TEXT giving the real explanation beside or beneath each primary element. Draft-status chip (round_rectangle, grey) top-right on each frame; step 1 uses "In progress" (black) instead of "Draft".
- **Cold-neutral palette in use:** #000000, #ffffff, #cccccc, #999999, #555555, #888888, #666666. No warm/sand/amber. Fonts on the site: Schibsted Grotesk (display), Instrument Sans (body), Sometype Mono (mono). On Miro, `plex_sans` for shape/heading text and `open_sans` for body/captions (the `unknown` font token is invalid on create; avoid it).
- **DSL gotchas to carry forward:** thin shapes (<~12px) fail the whole create batch; deletion = `layout_update` with the exact stored DSL block as old_string and empty new_string; `<a href>` links break TEXT parsing (use a DOC with markdown `[text](url)` for clickable links, as step 2's competitor URLs do); frame x/y drift on edits but child relative coords stay stable; always frame-scope (`?moveToWidget=`) to touch children.
